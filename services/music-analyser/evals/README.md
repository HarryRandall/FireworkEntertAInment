# Independent beat evaluation

The accuracy corpus is 22 full microphone recordings from
[GuitarSet 1.1.0](https://zenodo.org/records/3371780), licensed **CC BY 4.0**.
Attribution: Qingyang Xi, Rachel M. Bittner, Johan Pauwels, Xuzhou Ye and
Juan P. Bello, _GuitarSet: A Dataset for Guitar Transcription_, ISMIR 2018.
The source record's API identifies the licence as `cc-by-4.0`.

`guitarset.json` contains source JAMS `beat_position` observations, taking
`value.position = 1` as downbeats. Times are seconds from the original audio start.
These are dataset annotations, independent of ShowCrafter's predictions. Their
regular clocks originate from the dataset's recording/annotation procedure;
they are not fresh human taps and should not be interpreted as exact expressive
performance timing.

## Selection and training overlap

The manifest includes every accompaniment recording in fold 0 of
[the upstream v1.0 split](https://github.com/CPJKU/beat_this_annotations/blob/c3c47fd37d3074d9f8119f18bbf460f909609f22/guitarset/8-folds.split),
except `04_BN3-154-E_comp`, excluded because of the
[published annotation alignment erratum](https://github.com/marl/GuitarSet/issues/5).
The second reported bad recording is not in this fold. We do not alter labels to
make either tracker look better. Six guitarists cover bossa nova, funk, jazz, rock
and singer-songwriter styles, with nominal tempos from 68 to 187 BPM.

The **fold0** checkpoint was trained on the other seven folds. `final0` includes
GuitarSet in training, so it cannot establish held-out accuracy here. The microphone
capture is used rather than the pickup mix named in the model's split; it is the
same held-out performance and source annotation clock. This is a validation-fold
comparison, not a new independent test benchmark. It does not establish results
on full-band Jamendo, vocals, percussion, other metres or long recordings.

## Reproduce

From the repository root, after installing the pinned analyser requirements:

```bash
services/music-analyser/.venv/bin/python services/music-analyser/download_model.py
services/music-analyser/.venv/bin/python services/music-analyser/download_evaluation.py
services/music-analyser/.venv/bin/python services/music-analyser/evaluate.py
```

Audio and model files live in ignored `.cache/`; no new audio is committed.
HTTP range requests fetch selected archive members. ZIP CRC and per-recording
SHA-256 checks reject changed audio. Original annotation-member SHA-256 values
are recorded alongside the extracted labels. The model package, checkpoint,
licence, URL and SHA-256 live in `../beat-this-model.json`.

F-measure uses one-to-one event matches within 70 ms, over the whole recording,
including its opening beats. Missing and extra events count against the score.
There is no five-second startup exclusion. Tempo accuracy is Acc1 within 4% of
the median annotated beat interval, without accepting half or double tempo.
Scores are macro averages, so each recording has equal weight. The switch gate
requires higher beat and downbeat F-measure with no tempo-accuracy regression.

`report-local-cpu.json` records each track's two scores, tempo, complete pipeline
runtime, rhythmic tracking time, environment and model checksum. Decode,
segmentation, profiles and output validation are included; downloads are excluded.
Each track is run librosa first, then neural. First-track timings include cold
imports/model loading and later tracks share the process. Cached numba compilation
and order effects mean these are not deployment cold-start measurements.
Two Torch CPU threads are used; other library thread settings remain environmental.
Provider cost is zero; compute cost is **null**, because no Modal billing was measured.

## Sample label inspection

Visually inspected eight-beat RMS excerpts for `00_Rock1-90-C#_comp`,
`02_Funk2-108-Eb_comp` and `04_SS1-68-E_comp`. The funk excerpt shows several
clear attacks near the source beat lines; rock and singer-songwriter excerpts
also contain anticipations, subdivisions and weak beats. There is no obvious
uniform clock offset in these windows. Labels were left unchanged. This was
waveform inspection, not listening or a human confirmation of downbeat phase.
The inspection image is `/private/tmp/showcrafter-beat-label-hand-check.png`.

The old `baseline_v1.json`, `jamendo_fixtures.json` and `audio/` are retained as
historical regression material. Their expected features were generated by the
analyser itself. They are **not ground truth** and no longer drive the evaluation
or CI's accuracy gate.
