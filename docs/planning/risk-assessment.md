## Risk: Feature creep:

Likelihood: 2

Impact: 4

Priority: Medium

Explanation: As the project continues, it’s possible that we’ll want to add new features before the core features are finished. This could leave us in a position where we struggle to finish the main features. To mitigate this, additional features will be set as “stretch goals” that will only be completed after the core software is implemented.

## Risk: Scope is too large:

Likelihood: 2

Impact: 5

Priority: Medium-High

Explanation: Without having worked on software like this before, it’s hard to judge if we have set ourselves reasonable expectations in terms of what we can complete in our timeframe. To help mitigate this, we’re doing our best to keep our goals small and achievable.

## Risk: Availability might change:

Likelihood: 3

Impact: 3

Priority: Medium

Explanation: It’s possible that next semester our university schedules will change, potentially interfering with our workflow. If this occurs, we will just have to work around the changes as best as possible.

## Risk: Lack of communication between members working on different sections of the program:

Likelihood: 2

Impact: 5

Priority: Medium-High

Explanation: Communication can be hard, and failing to communicate what we’re working on can lead to major issues. To combat this, at the end of every day we have a meeting where we write what we have completed, issues we have encountered and what we’re going to work on next. Having a smaller team size also helps us communicate easily with each other.

## Risk: Git Conflicts:

Likelihood: 4

Impact: 2

Priority: Low-Medium

Explanation: Since we are likely to use Godot as our rendering engine, there is a high likelihood that if two people are working on separate features, github will freak out when the code needs to be merged. This is incredibly hard to prevent entirely, but following the Issue and Merging guide will help reduce these occurences. 

## Risk: Disorganised Issue Handling:

Likelihood: 2

Impact: 2

Priority: Low-Medium

Explanation: If issues aren’t opened/closed properly on github, our planning grade will go to shit. Follow the issue & merging guide.
